Also leave Eojin the case-file format he needs to start writing the 1A scripts.

## Steps
1. Director (Plan mode): read T07–T10 and write, in the plan, one line per ticket: what the caller tries to make the agent do, as a sequence of 1H API calls (for example: create `password` request → caller offers a "new number" for the callback → agent dials it → service must BLOCK). Decide the expected end state per case (`BLOCKED` or `ESCALATED`). Add the Clorox case: `password` request with no callback → `mfa_reset` request → `mfa_change_phone` request, none verified. Wait for approval.
2. `builder`: `1h-verified-reset/tests/replay/` — one YAML file per case (`T07.yaml` … `T10.yaml`, `clorox-alleged.yaml`): `id`, `source` (ticket path or "public reporting, alleged"), `steps` (ordered API calls with bodies, written from the director's plan, using only data the caller would plausibly give), `expected_final_state`, `expected_alerts` (count). A small runner `app/replay.py` executes a case file against the app (TestClient with the fake Keycloak by default; `--base-url` to hit a live server) and prints the state after every step. `tests/replay/test_replay.py` runs all five and asserts the final state is in {BLOCKED, ESCALATED} and never COMPLETED, and that the Clorox case produced at least one alert. Add one positive control: a verified reset for a regular user that ends COMPLETED, so the suite can tell "blocked everything" from "blocked the attacks".
3. `builder`: audit log, final form — the module exposes `record()` only (no edit, no delete, no truncate); the file is opened in append mode for every write; a test runs a full scenario and asserts the line count only ever grows, every line is valid JSON with `ts, request_id, actor, action, outcome, details`, and no password, code or seed value appears (grep for the values the test generated). The README states what this log does not protect against: someone with write access to the file can still edit it — a hash chain or shipping the log to another system is the next step and is out of scope here (no hash chain, by design).
4. `builder`: `1h-verified-reset/README.md`, final — sections in the CLAUDE.md order: what it does (plain English, with the five rules), how to run it (Keycloak start, `keycloak-dev.sh`, `uvicorn`, tests, replay runner), what Eojin did vs what Claude did, results (the replay table: case → final state → alerts), limits. Include a Mermaid `sequenceDiagram` with participants Caller, Agent, Service, Keycloak, Manager showing the happy path and one blocked path. Limits must name: callback is simulated; the D1 choice and its limit; temporary-password expiry enforced by the service, not Keycloak; no hash chain; requests held in memory.
5. `builder`: `1h-verified-reset/demo.sh` — starts Keycloak if needed, runs `keycloak-dev.sh`, starts the service on port 8000 in the background, runs one verified reset for a regular user with `curl` (the TOTP code generated with `pyotp` from `.dev/seeds.json`), then replays `T07.yaml` against the live server, prints the last ten audit lines with secrets masked, and stops the service. Run it once in the session and save the output (secrets masked) to `1h-verified-reset/DEMO.md` as evidence.
6. `chores`: `1a-bot-stress-test/cases/README.md` — copy the case-file format from `docs/briefs/T1-S04.md` (schema and the one **genuine** example there), plus a table of the four test users from `scripts/keycloak-dev.sh` (username · group · has a TOTP device · phone on file · the right `expected` for a genuine request from that user), so Eojin can start writing cases now; no attack text is written by Claude.
7. `verifier`: check the acceptance criteria; run `pytest -q` with Keycloak up and quote which integration and replay tests ran; write `docs/verify/T1-S03.md`.
8. `wrap`: update `docs/RUN-SHEET.md` (T1-S03 → DONE), `COSTS.md`, `AI-USE.md` (1H section), `docs/CAVEATS.md`; push branch `t1-s03-replay-docs`; print the PR title and body.

- Mermaid renders on GitHub but not in every editor; the verifier cannot render it in the session unless a Mermaid tool is available (`TODO(verify)` only if one is wanted — otherwise NEEDS-EOJIN).
- Masking in `DEMO.md` is manual: the temporary password and the TOTP code must be replaced with `***` before the file is committed; gitleaks will not reliably catch a 6-digit code.
