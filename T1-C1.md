## The ten "why" questions (ask in this order)
1. Why does the SOP put the callback to the number on file *before* the one-time code, and not the other way round?
2. Why must the callback go to the number already on file — and what exactly should the agent do when the caller says "I've got a new number, call me on that"?
3. Why does the service answer a step called out of order with HTTP 409 and an audit line, instead of just running the step or ignoring it?
4. Why is manager approval required only for the `privileged` group? What would go wrong, in a 50-person credit union, if every reset needed a manager?
5. Why is the temporary password valid for 60 minutes, and why does the service — not Keycloak — enforce that limit?
6. Why does the audit log record that a temporary password was issued but never the value, and never the one-time code either?
7. Why is the audit log append-only JSON lines, and what can it *not* protect against without a hash chain or shipping the log somewhere else?
8. Why does an MFA-method change within 24 hours of a reset raise an alert even when that change was itself verified? Which public case is this rule modelled on, and what word must always go next to that company's name?
9. Why do the unit tests use a fake Keycloak while the integration tests are marked `keycloak` and skip when the server is down — what does each kind of test prove, and what does neither prove?
10. Why do the replay tests reuse exactly the four 1E tickets T07–T10 and the alleged Clorox sequence, and why does the suite also need one case that *succeeds*?

<details>
<summary>Grading notes — for the director; Eojin, do not open this before the class</summary>

1. The callback is the cheapest check and uses a channel the caller did not choose (out-of-band); if it fails, nothing else is spent. A code first would prove device possession but not that the voice on the line is the person on file.
2. The number on file is the one piece of data the caller cannot change by talking; "call me on a new number" turns the callback into a check the attacker controls. The agent dials the number on file; if there is no answer, the request is BLOCKED and the person can come back through a verified channel (manager, in person).
3. A 409 makes the attempt visible (audit line) and keeps the state machine the single source of truth; silently running the step would let an agent — or a bot — be talked into skipping checks.
4. Privileged accounts are where a takeover does the most damage, so the extra cost is worth it there; applying it everywhere would make managers rubber-stamp dozens of requests and train everyone to approve without reading.
5. Sixty minutes bounds the window in which a leaked temporary password is useful. Keycloak's "temporary" flag only forces a change at next login; it has no time limit, so the service tracks `expires_at` and rotates the password.
6. The log is read by people and shipped to other systems; a password or code in it is a second copy of a secret. Recording the event proves what happened without creating something to steal.
7. Append-only means nothing legitimate ever rewrites history and the line count only grows; but anyone with write access to the file can still edit it — a hash chain, or sending each line to a separate log system, is what would catch that. It is out of scope and the README says so.
8. Public reporting (and Clorox's lawsuit against Cognizant — always "alleged") describes reset → MFA reset → MFA phone change in quick succession; the rule catches the pattern even when each step looked fine alone. AL26-010: "closely monitor MFA reset, recovery, and device re-enrolment processes".
9. Unit tests prove the service's rules with a predictable stand-in and run everywhere, including CI; integration tests prove the real Keycloak calls work and only run where a server exists. Neither proves a human or an AI agent will follow the procedure — that is 1A.
10. T07–T10 are the exact calls the SOP was written against, so the test is tied to the casebook, and the Clorox sequence is the public pattern. Without a passing case the suite could be "blocking everything" and still look green.
